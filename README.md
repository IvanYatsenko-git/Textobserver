# TextObserver

TextObserver — настільний застосунок для роботи з текстовими документами та пошуку фрагментів, пов'язаних із заданими тезами. Інтерфейс працює на Electron, а пошуковий бекенд — на Python. Індекс і пошукові обчислення зберігаються локально; модель BGE-M3 може завантажуватися з Hugging Face під час першого запуску.

## Можливості

- Відкриття та редагування текстових і Markdown-документів.
- Імпорт PDF і DOCX.
- Сегментація тексту на фрагменти зі збереженням координат у документі.
- Локальний пошук на основі BGE-M3, BM25 і прямого збігу термінів.
- Зважене злиття результатів семантичного й лексичного пошуку.
- Підсвічування знайдених фрагментів і відстеження покриття тез під час редагування.
- Бенчмарк пошуку на контрольних запитах із метриками Hit@K, MRR і Recall@K.

## Як працює пошук

Застосунок використовує гібридний пошук: семантичні результати BGE-M3 з ChromaDB та лексичні оцінки BM25 об'єднуються з оцінкою перекриття ключових слів. Поточні ваги в реалізації: `0.35` для BGE-M3, `0.35` для BM25 і `0.30` для перекриття ключових слів. Пошукові канали виконуються послідовно, після чого результати об'єднуються; CrossEncoder не входить до production-пошуку. Альтернативні reranker-моделі залишені лише для порівняння в бенчмарку.

Параметри й результати залежать від корпусу та конфігурації. Бенчмарк у `test/` призначений для оцінювання саме на цьому тестовому наборі й не гарантує такі самі метрики для інших документів.

## Структура проєкту

```text
TextObserver/
├── assets/                          # Іконки застосунку
├── src/
│   ├── main/main.js                 # Electron main: вікно, системні дії, запуск Python
│   ├── preload/preload.js           # Безпечний міст IPC між main і renderer
│   ├── renderer/
│   │   ├── index.html               # Розмітка вікна
│   │   ├── renderer.js              # Інтерфейс та логіка клієнта
│   │   └── styles.css               # Стилі інтерфейсу
│   └── utils/
│       ├── segmentation.js          # Сегментація документа
│       ├── coverage-tracker.js      # Відстеження покриття під час редагування
│       └── overlay.js               # Декорації й маркери в редакторі
├── python_backend/
│   ├── app_backend.py               # Індексація, IPC та production-пошук
│   ├── search_utils.py              # Очищення, токенізація й утиліти пошуку
│   ├── benchmark.py                 # Бенчмарк пошукових режимів
│   ├── test_corpus_benchmark.py     # Оцінювання на корпусі з test/
│   ├── evaluate_thesis_search.py    # Оцінювання пошуку за тезами
│   ├── requirements.txt             # Python-залежності
│   └── BENCHMARK.md                 # Детальні інструкції до бенчмарку
```

`node_modules/`, `.venv/`, `dist/`, згенерований renderer bundle, локальна ChromaDB та весь каталог `test/` ігноруються Git. Тестові документи, запити й звіти залишаються локально та не публікуються разом із кодом.

## Встановлення та запуск у Windows

Потрібні Node.js/npm і Python. З кореня проєкту виконайте:

```powershell
npm install
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r python_backend\requirements.txt
npm start
```

Під час першого запуску BGE-M3 може бути завантажена локально, тому потрібне мережеве з'єднання та вільне місце на диску. Після завантаження модель виконує ембеддинги локально. За бажанням створіть `.env` для ключів зовнішніх сервісів; файли `.env*` ігноруються Git, крім шаблону `.env.example`.

## Бенчмарк

Інструкції й параметри наведені в [`python_backend/BENCHMARK.md`](python_backend/BENCHMARK.md). Щоб запустити бенчмарк на корпусі з `test/` без завантаження альтернативних моделей:

```powershell
.\.venv\Scripts\python.exe python_backend\test_corpus_benchmark.py --manual-only --skip-e5
```

Щоб використати також збережені синтетичні запити, приберіть `--manual-only`. Для генерації нового набору запитів Gemini потрібен `GEMINI_API_KEY`; ключ використовується лише цим кроком, а не для звичайного пошуку.

Каталог `test/` не входить до репозиторію. Для запуску корпусного бенчмарку після клонування потрібно окремо додати туди власні тестові документи й файли контрольних запитів. Без цих локальних даних бенчмарк на корпусі виконати не вдасться.

## Збірка

```powershell
npm run build
```

Electron Builder налаштований на створення інсталяторів для Windows, macOS і Linux. Перед розповсюдженням потрібно окремо перевірити наявність Python та залежностей на цільовому комп'ютері: ця конфігурація не включає готове Python-оточення й модель BGE-M3 у пакет.

## Дані та публікація

Каталог `test/` виключено з Git, щоб тестові документи, назви файлів і звіти залишалися локальними.
